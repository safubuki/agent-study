## Subagents（サブエージェント）

- 子は独立した文脈・独自のシステムプロンプト・独自のツール権限で動く。利点：文脈を汚さない、ツール制限を強制できる、設定を再利用できる、専門化できる、安いモデル（Haiku）に回せる。
- **メインの会話でやるべき**とき：やり取りが多い、計画・実装・テストが文脈を大きく共有する、小さな変更、**遅延が問題になる**（新しい子は文脈集めからやり直すので時間がかかる）。
- **子に任せるべき**とき：出力が冗長でメインに要らない、ツール制限を強制したい、自己完結して要約を返せる。
- 子はさらに子を呼べる（既定でメインから **3階層下まで**）。同時実行は既定 **20体まで**。
- Claude は依頼内容・各サブエージェントの `description`・現在の文脈から**自動で委任**する。
- **フォーク**：親の会話をそのまま引き継ぐ子。対話セッションでは**フォークモードが既定でオン**で、Claude が起動した子は**既定でバックグラウンド**で動く。

## Agent teams（エージェントチーム、実験的機能）

- 1つのセッションがリードになり、複数の Claude Code セッション（チームメイト）が**共有タスクリスト**と**相互メッセージ**で協調する。サブエージェントは結果を親に返すだけなのに対し、チームメイトは互いに直接話し、議論・反証し合える。
- 向く：調査とレビュー、独立した新モジュール、**競合する仮説を並行して検証**するデバッグ、層をまたぐ変更。向かない：順番に依存する仕事、同じファイルの編集、依存の多い仕事。
- トークンは大幅に増える。まず **3〜5人**から。1人あたり 5〜6 タスクが目安。「集中した3人は散らばった5人に勝つことが多い」。
- 有効にすると、Claude が自分で名前を付けた子がチームメイトとして起動するので、**頼まなくてもチームができる**ことがある。リードがチームの人数やタスク分割を決める。
- 制限：ネスト不可、リード固定、セッション再開でチームメイトは戻らない など。

## Best practices（ベストプラクティス）

- 「新しいセッションの最初の素直なプロンプトで、たいてい正しく動くように作られている」。既定で、独立した作業は Claude が自分でサブエージェントに任せる。
- 子が元を取る場面：独立した作業の同時進行、長い出力（テスト全件・広い検索）の隔離、**書いた過程を見ていないレビュー役**、メインより少ないツールで動かしたいとき。
- 子のコストは主にトークン。新しい子は文脈集めからなので、**その場でやるより遅いこともある**。既定では同じモデル（か小さいモデル）が同じ仕事をするので、「並列」か「新しい目」は得られても、**賢い答えは得られない**。
- レビュー役に「問題を探せ」と頼むと必ず何か見つける。全部直すと不要な抽象化や起こりえないケースのテストが増える（だから「スタイルは無視」と範囲を絞る）。
- 大量の機械的変更は `/batch` が 5〜30 単位に自動分割し、それぞれ別の worktree で進める。
- **「やめていいこと」表**（抜粋）：
  | 昔のアドバイス | なぜ不要になったか |
  |---|---|
  | コンテキスト窓が最大の制約、積極的に管理せよ | 多くのモデルが 1M トークン窓を持ち、圧縮も自動。使い切ることはまれ |
  | 文脈を守るためにサブエージェントを使え | 文脈切れはもうほとんど問題でない。並列化・雑多な出力の隔離・独立レビューには今も有効だが、どれも追加のトークンがかかる |
  | より良い答えのためにサブエージェントに任せよ | 同じ仕事を子に渡しても答えは良くならない。新しいレビュー役が効くのは、推論過程を見ていないからで、委任とは別物 |
  | 重要事項は大文字や IMPORTANT で強調 | 今のモデルは普通の文で従う。強調は過剰適用を招く。曲げられない規則はフックや拒否ルールに |
  | 「最後までやれ」「手を抜くな」と書く | 今のモデルは合意した仕事を続ける。過剰作業を招く。代わりに合格すべきチェックを与える |
  | アーキテクチャやファイル構成を CLAUDE.md に書け | Claude はリポジトリを自分で読む。そこに無いことだけ書く |
