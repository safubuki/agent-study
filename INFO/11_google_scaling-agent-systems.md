## 要点

- 道具・プロンプト・計算量をそろえたうえで、**構成だけを変えて**比較した大規模実験。
- 5つの構成：
  | 構成 | 中身 |
  |---|---|
  | 単体（SAS） | 1体がすべてを順番に行う |
  | 独立（Independent） | 複数体が**連絡なしに**並列作業し、最後に結果をまとめる |
  | 中央集権（Centralized） | 親（オーケストレーター）が子に配り、結果を統合する |
  | 分散（Decentralized） | 子同士が直接やり取りして合意する |
  | 混合（Hybrid） | 階層的な監督＋子同士のやり取り |
- 主な結果（ブログ版の数字）：
  - **分解できる仕事**（Finance-Agent：財務分析）では、中央集権型が単体より **+80.9%**。
  - **順番に積み上げる仕事**（PlanCraft：計画）では、**どのマルチエージェント構成も 39〜70% 悪化**。連絡のオーバーヘッドが思考を分断するため。
  - **誤りの増幅**：独立型は単体の **最大17.2倍** 誤りを増やし、中央集権型は **4.4倍** に抑えた。親が「検証の関所」になるため。
  - **道具が多い仕事**（16個以上のツールを使うコーディングなど）ほど、連携コストが不釣り合いに大きくなる。
  - 単体の性能が十分高い領域では、連携による上積みが小さくなる（能力の飽和）。
  - 仕事の性質（分解しやすさ・道具の数など）から最適な構成を当てるモデルを作り、未知の設定の **87%** で正解。
- 論文 v3 の要約では、比較は 260 構成・6ベンチマーク・3系統の LLM、単体比の差は **+80.8%〜−70.0%**。ブログ（180構成）とは版の違いで数字が少しずれる。

## 注意点

- 2025年後半〜2026年前半のモデルでの実験。「仕事が並列に分解できるか・順番に依存するか」で答えが逆転する、という骨格は、モデルが変わっても残りやすい知見。
