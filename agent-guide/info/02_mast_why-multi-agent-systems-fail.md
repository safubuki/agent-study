# 論文「Why Do Multi-Agent LLM Systems Fail?」（MAST）

| 項目 | 内容 |
|---|---|
| 種別 | 論文（arXiv:2503.13657、NeurIPS 2025 Datasets & Benchmarks） |
| 著者 | Mert Cemri, Melissa Z. Pan, Shuyi Yang ほか（UC Berkeley ほか。Ion Stoica, Matei Zaharia, Joseph E. Gonzalez らを含む） |
| 公開日 | 2025-03-17（v3: 2025-10-26） |
| 鮮度 | **古**（v3 から約12か月）。対象モデルは GPT-4 / Claude 3 / Qwen2.5 / CodeLlama 世代 |
| URL | https://arxiv.org/abs/2503.13657 |

## 要点

- 7つのマルチエージェント枠組み（ChatDev、MetaGPT など）の実行記録を分析し、失敗を **3カテゴリ14種類**に分類（MAST）。注釈者間一致 κ = 0.88。1,600件超の注釈付き記録を公開。
- マルチエージェントは主要ベンチマークで**単体よりわずかしか良くならない**ことが多い、という問題意識から出発。
- 失敗モードと出現割合（論文 v3 の表より）：

| カテゴリ | 失敗モード | 割合 |
|---|---|---|
| FC1 システム設計 | 1.1 タスク仕様に従わない | 11.8% |
| | 1.2 役割仕様に従わない | 1.5% |
| | 1.3 同じ手順の繰り返し | 15.7% |
| | 1.4 会話履歴の喪失 | 2.8% |
| | 1.5 終了条件を知らない | 12.4% |
| FC2 エージェント間の食い違い | 2.1 会話のリセット | 2.2% |
| | 2.2 確認すべきときに聞かない | 6.8% |
| | 2.3 タスクの脱線 | 7.4% |
| | 2.4 情報を渡さない | 0.85% |
| | 2.5 他エージェントの入力を無視 | 1.9% |
| | 2.6 考えと行動の不一致 | 13.2% |
| FC3 検証 | 3.1 早すぎる終了 | 6.2% |
| | 3.2 検証なし・不十分 | 8.2% |
| | 3.3 誤った検証 | 9.1% |

- 検証（FC3）の3項目だけで合計 **約23.5%**。検証役が「コンパイルが通るか」程度の浅い確認しかしていない例が多い。高いレベルの目的チェックを足すと ProgramDev で約 +15.6%。
- 役割仕様を明確にし最終決定者を決める（ChatDev で CEO に最終決定権）と約 +9.4%。
- ただしプロンプトや構成の小手先の修正では改善は限定的。検証・通信手順・状態管理といった**構造的な対策**が必要、と結論。
