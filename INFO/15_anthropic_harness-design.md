## 要点

- 長時間かけてアプリを丸ごと作るための3体構成：
  - **プランナー**：短い依頼を製品仕様に膨らませる。**細かい実装は指定せず**、成果物と大枠の設計に集中（上流の誤りが下流に連鎖しないように）。
  - **ジェネレーター**：アプリを作る（Opus 4.5 版ではスプリント単位で1機能ずつ）。
  - **エバリュエーター**：Playwright で実際にアプリを操作し、基準ごとの閾値で採点。1つでも下回れば不合格。
- 評価役を分ける理由：**エージェントは自分の仕事を採点すると甘くなる**。別の評価役を厳しく調整する方が、作り手に自己批判させるよりずっと扱いやすい。
- **スプリント契約**：作る前に「何を作り、どう確かめれば完了か」を作り手と評価役が合意する。やり取りはファイル経由。
- **モデル更新で外したもの**：
  | 部品 | 変化 |
  |---|---|
  | 文脈のリセット | Sonnet 4.5 は文脈が埋まると焦って雑になる癖があり必須だった → Opus 4.5 で癖がほぼ消えたので廃止。自動圧縮つきの1セッションに |
  | スプリント分割 | Opus 4.6 で、分割しなくても一貫して作れるようになったので廃止 |
  | スプリントごとの評価 | 最後に1回だけの評価に変更 |
  | プランナー | 維持（ないと作り手が仕事の範囲を小さく見積もる） |
  | 評価役 | 条件付きで維持：**今のモデルが単独では確実にこなせない難しさのときだけ**元が取れる |
- 基本原則：**ハーネスの部品はどれも「モデルが単独ではできないこと」という前提を埋め込んでいる**。その前提は間違っているかもしれず、モデルが良くなれば古くなる。不要になった部品は外し、新しいモデルでできるようになったことには新しい部品を足す。
- コスト：レトロゲーム作成で、単体 20分・9ドル に対し、フル構成 6時間・200ドル（20倍超）。
