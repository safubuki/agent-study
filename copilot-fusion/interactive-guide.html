COPILOT-FUSION — 初めてでも 5 分でわかるハーネスと Fusion

AI の現場監督「Copilot ハーネス」と
賢くモデルを使い分ける「Copilot Fusion」

ハーネスとは、考える「AI モデル」と操作する「ツール・MCP」の間で会話や承認を管理する実行プログラムのことです。 そして、問題の難しさに応じて複数の解き方を自動で選んでくれる仕組みが Copilot Fusion です。

1Fusion の 3 つの解き方を紙芝居で比べる 2旧 Local vs 新 Copilot「窓を閉じる実験」 3移行で「MCP が消えた！」を直す 4 コマ物語 4Auto・サブエージェントとの違い＆安全注意
STEP 1 — Copilot Fusion の 3 つの動き方

同じ依頼でも、難しさに応じて「1体 / 昇格 / 並列批評」を自動選択

どんな場面？ あなたが VS Code で「アプリの不具合を直して」と頼みました。Fusion は問題の難しさと effort（Standard / High / Max）を見て、3 つの進め方から最適なものを選びます。どの方式でも最後に返ってくる返答は 1 つです。
① 見たい解き方を 1 つ選んでください

STEP 2 — なぜ Copilot ハーネスへ移行するの？

VS Code のウィンドウを閉じても、裏側の Agent Host が作業を続ける

どんな場面？ 旧 Local ハーネスは 2027 年 2 月までに削除予定 です。新しい Copilot ハーネスとの一番わかりやすい違いを、「作業中に VS Code のウィンドウを閉じる」実験で見てみましょう。
ボタンを押して、作業中に VS Code の画面を閉じてみましょう

STEP 3 — 移行でいちばん多いトラブル

「Copilot ハーネスに替えたら MCP が一覧から消えた！」を直す 4 コマ

どんな場面？ 旧 Local で使えていた社内文書検索 MCP（teamDocs）が、Copilot ハーネスに切り替えた瞬間に一覧から消えてしまいました。なぜ消え、どう直せばよいか 4 コマで理解しましょう。

🔍 もっと詳しく：旧 .vscode/mcp.json → 新 .mcp.json の書き換え例を見る

ルートキーを servers → mcpServers へ、認証を ${input:docs-key} → ${DOCS_API_KEY} へ変えます。 

// 新：ワークスペース直下の .mcp.json（Copilot ネイティブ形式）
{
  "mcpServers": {
    "teamDocs": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "headers": { "Authorization": "Bearer ${DOCS_API_KEY}" }
    }
  }
}
SUMMARY — 混同しやすい違いと最重要の安全注意

Auto・Fusion・サブエージェントの違い ＆ 3 問チェック

仕組みなにをする？会話・文脈の扱い
Auto最適な 1 モデルを自動選択して最後まで実行1 つの会話内
Copilot Fusion難易度と effort に応じて Single / Cascade / Critique を自動選択1 つの会話内（最終返答は必ず 1 つ）
サブエージェント別担当の AI 作業員に仕事そのものを分担（task 委任）子が独立した記憶で動く
🚨 使う前に絶対知っておくべき安全注意：自動ロールバックはありません！
Cascade や Critique で初稿案が破棄されても、初稿モデルがすでに行ったファイル変更は自動で元に戻りません。Fusion の返答を読んだら、必ず Git 差分とテスト結果 を確認しましょう。
