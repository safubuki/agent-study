AGENT-GUIDE — 初めてでも 5 分でわかる「サブエージェント」入門

AI に仕事を分担させると本当に速くなる？
実測と動きで「効く場面・ダメな場面」を理解する

サブエージェントとは、メインの AI が仕事の一部を任せるために呼び出す「別の AI 作業員」のことです。 いちばんの価値は速さよりも「メインの AI の頭（記憶）を雑音で汚さないこと」。4 つの体験で本質をつかみましょう。

11人で調べる vs 調査係に任せる（記憶の違い） 2なぜ分担したのに遅くなった？（A/B/C 実測レース） 3分担が効く仕事・逆に遅くなる仕事 4モデルが進化しても「残すべき 3 原則」
STEP 1 — サブエージェント最大のメリット

別室で調べさせて「要点メモ 1 枚」だけ持ち帰ってもらう

どんな場面？ 50 個のファイルと長いエラーログの中から、バグの原因を探してほしい場面です。メイン AI が自分で全部読むと、記憶（コンテキスト）が雑音でパンパンになってしまいます。
ボタンを押して、メイン AI の記憶の使われ方を比べましょう

元の依頼 (500 tok)
💡 いま起きていること ボタンを押すと、大量のログを読んだときの記憶の差が動きで分かります。
STEP 2 — 実際の比較実験（report_01-profile.md）

分担（B）が 1人（A）より遅かったワケと、スクリプト統合（C）の大逆転

どんな実験？ 同じ自己紹介ページを 3 通りで作り比べました。A（1人）、B（親が設計→HTML/CSS/JS の 3 体が並列作成→最後に親 AI が 1 ファイルへ書き写し統合）、C（B と同じだが、最後の統合だけ Node.js スクリプトに任せる）。同時スタートで比べてみましょう！
B の「赤いバー（AI 書き写し統合）」と C の「緑のバー（1.1秒）」の差に注目！
設計・発注 並列部品づくり AI 書き写し統合 (129秒) スクリプト統合 (1.1秒)
0.0 秒
方式 A：1人（Opus が全部書く）0.0秒 / $1.15
方式 B：分担（統合も AI が 4万字を書き写す）0.0秒 / $1.68
方式 C：分担 ＋ 統合だけスクリプト（1.1秒）0.0秒 / $1.05
💡 実況ポイント 「▶ レースを再生する」を押すと、3 方式が同時スタートします。
🔍 もっと詳しく：スクリプト作成費は何回目で元が取れる？

統合スクリプト（merge-parts.js）を最初に AI に作らせるコストは 99.1 秒・0.43 USD でした。 方式 B と比べると1 回目から即回収、方式 A と比べても時間は 2 回目・コストは 5 回目から方式 C がお得になります。

STEP 3 — 並列化の向き・不向き

「独立した調べもの」は 2〜5 体で爆速。「順番依存・同時執筆」は逆効果

どんな疑問？ 「どんな仕事でも 5 人に分けたら速くなるの？」——Google / MIT や Cursor の大規模実験では、仕事の性質によって結果が正反対に分かれました。3 つの仕事を選び比べてみましょう。
試したい仕事の種類を選んでください
STEP 4 — 長く効くエージェント設計のコツ

AI が賢くなると、念押しや手順縛りは不要になり「3 本柱」だけが残る

どんな考え方？（The Bitter Lesson：苦い教訓） モデルの弱点を補うために足した細かい工夫は、次の世代のモデルが出ると逆に足かせになります。時代を切り替えて「外せる工夫」と「ずっと残すべき 3 本柱」を確認しましょう。
時代を切り替えて比べてください
🔍 もっと詳しく：定義ファイルの書き方（Claude Code と Copilot の違い）を見る

定義ファイルは「上段（YAML 設定）＋下段（役割の本文）」の 2 段構造です。文章で「編集禁止」とお願いするより、tools から書き込み道具を外すのが最も確実です。なお Copilot（VS Code）では子の料金ランクを親より高くできない点に注意します。 

# Claude Code (.claude/agents/readonly-reviewer.md)
---
name: readonly-reviewer
model: sonnet
tools: Read, Grep, Glob   # ← Write / Edit を渡さない＝物理的に編集不可！
---

SUMMARY — 定番 5 パターンと 3 問チェック

まず 1 人で試し、足りないところだけ 5 つの型から選ぶ

パターン名ひとことで向いている場面
① 調査係読取専用の子が要約だけ返す広いコード検索、長いログ解析
② 配ってまとめる独立部品を並列作成 → 1人/スクリプト統合独立モジュール調査、ファイル分離分担
③ 作り手＋チェック作成過程を見ない別 AI が客観採点合格基準が明確で品質重視の仕事
④ 相談役安いモデルが実行し難所だけ Opus に相談量が多くコストを抑えたい仕事
⑤ 受付と専門窓口入口で分類して専用道具の担当へ振る似た道具が多くて誤選択が起きる業務
