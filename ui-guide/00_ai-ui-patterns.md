# 00. 一次情報に基づく AI アプリの UI パターン体系（全 7 パターン）

AI 機能を持つアプリを作るとき、「チャット欄を置けばいいの？ それともスライダーや自動処理がいいの？ 他にも型があるの？」と迷うことはよくあります。

この章では、感覚や思いつきの分類ではなく、**実際に大手テック企業や UX 研究機関が公開している一次ガイドライン**に基づいて、現在確立されている **代表的な 7 つの AI UI パターン** と、その根拠となる **4 大フレームワーク** を整理します（詳しい出典は [info/README.md](info/README.md) を参照してください）。

> [!NOTE]
> **用語の扱い方について**
> たとえば「AI 裏方型」といった表現は公式の専門用語ではありません。一次情報では **Apple HIG の `Invisible ML`（不可視の機械学習）** や **NN/g の `Ambient AI`（環境溶け込み型）**、**The Shape of AI の `Tuners`（調整つまみ）** といった明確な用語で定義されています。本ガイドでは必ず **正式な一次用語と提唱元** を先に示し、そのうえで日本語での分かりやすい言い換えを添えています。

> 実際の操作感の比較・ポチポチ診断・AI 相談プロンプト生成は、[動的ガイド（interactive-guide.html）](interactive-guide.html) で試せます。

## 1. 根拠となる 4 大一次フレームワーク

AI アプリの UI 設計には、業界で広く参照される 4 つの代表的な一次ガイドラインがあります。

| 提唱元・資料 | 何を決めているガイドラインか | 特に押さえるべき核心 |
|---|---|---|
| **Nielsen Norman Group (NN/g)**<br/>（UX 研究の権威） | AI 時代の画面構造分類とユーザビリティ研究 | **「AI Chat Is Not Always the Answer（チャットが常に正解ではない）」**＝通称 **Conversation Trap（会話の罠）** を警告。Chat / Canvas / Inline / Ambient / Generative UI の 5 構造を整理 |
| **Apple**<br/>Human Interface Guidelines (Machine Learning) | AI の「見え方」と「介入タイミング」の設計軸 | **Visible（見える）vs. Invisible（見えない）**、**Proactive（先回り提案）vs. Reactive（求めに応じて応答）**、**Implicit vs. Explicit Feedback** の 3 軸を定義 |
| **Google (PAIR)**<br/>People + AI Guidebook | 人間中心の AI 設計プロセスと信頼・制御 | **Implicit（暗黙的）vs. Explicit（明示的）フィードバック** の設計、説明可能性（Explainability）、エラーからの優雅な回復（Graceful Failure） |
| **Microsoft**<br/>Guidelines for Human-AI Interaction (CHI 2019) & HAX Toolkit | 時間軸に沿った **18 の Human-AI 指針（G1〜G18）** | 初期（何ができるか明示 G1〜G2）→ 操作中（文脈適合 G3〜G6）→ 誤り時（簡単な修正・中止 G7〜G10）→ 継続利用（G11〜G18）。近年は自律エージェント UI にも適用 |

さらに、実在する AI 製品の UI 部品を分解したパターン集として **The Shape of AI（Emily Campbell）** が広く参照されており、スライダーや選択肢などのパラメータ調整部品を **`Tuners`（チューナー＝調整つまみ）**、AI の暴走を防ぐ制御を **`Governors`（ガバナー＝制御弁）** と名付けています。

## 2. 代表的な 7 つの AI UI パターン（一次用語 → 分かりやすい解説）

「チャットか、チャットなし（裏方）か」の 2 択や 4 択だけではなく、実務の AI アプリでは以下の **7 パターン** が使われており、多くは **複数を組み合わせて設計** します。

```text
  【人が細かく言葉で指示する】 ◀───────────────────────▶ 【AI が文脈を読んで自然に動く】

   ① Chat          ② Canvas        ③ Inline        ④ Tuners /      ⑤ Ambient /
   (会話・チャット) (成果物並列)    (その場補助)     Hybrid          Invisible ML
                                                   (調整UI＋一言)   (環境溶け込み・不可視)

   【さらに高度な出力・自律実行】
   ⑥ Generative UI（AI が表・フォーム・カードなど UI 部品そのものを動的生成）
   ⑦ Agentic Workspace（自律エージェントの計画提示・進捗タイムライン・承認ゲート）
```

---

### ① Conversational / Chat（会話・チャット型）
- **一次出典**：NN/g / The Shape of AI
- **どんな UI か**：メッセージ入力欄と会話タイムラインで対話する、もっとも有名な形。
- **向いている場面**：毎回内容が違う相談、調べもの、ブレインストーミングなど、**ゴールが最初から決まっていない探索作業**。
- **注意点（NN/g の警告：Conversation Trap）**：定型業務や設定変更まで全部チャットにすると、「毎回文章を打つ認知負荷」と「何ができるか見えない問題」が起きます。**最初の画面にお題ボタン（Wayfinders / Prompt Suggestions）を置く**のが定番の緩和策です。

---

### ② Canvas / Artifact Workspace（キャンバス・成果物並列型）
- **一次出典**：NN/g / OpenAI ChatGPT Canvas / Anthropic Claude Artifacts
- **どんな UI か**：左側（または片側）で指示を出し、右側（広いワークスペース）に **文書・コード・設計図などの成果物の最新版** を常時表示して反復編集する形。
- **初期案はどうやって出す？**：最初は普通のチャットと同じように「○○の店頭 POP の初期案を作って」と 1 回頼みます。AI が「これは 1 つの独立した成果物だ」と判断して右側の Canvas を開き、第 1 版を生成するところからスタートします。
- **向いている場面**：記事執筆、メール下書き、仕様書、ソースコードなど、**1 つの成果物を何度も手直しして仕上げる作業**。
- **メリット**：チャット履歴をスクロールして「どれが最新版？」と探す必要がなくなり、部分選択して書き直したり、**Undo（版戻し）** や手動編集もしやすくなります。

---

### ③ Inline / Contextual Assistance（インライン・文脈補助型）
- **一次出典**：NN/g（Inline Micro-Interactions）/ Apple HIG（Writing Tools）/ Microsoft Copilot
- **どんな UI か**：既存の画面・エディタ・入力フォームの **「いま操作しているまさにその場」** に、「要約する」「丁寧に書き直す」「続きを補完する」といった小さな AI アクションが現れる形。
- **向いている場面**：既存の業務アプリや文書エディタの中で、**別画面のチャットへ移動させずにサッと補助したい** 場面。
- **メリット**：ユーザーが慣れ親しんだ既存の操作感（メンタルモデル）を壊さずに AI の恩恵だけを足せます。
- **注意点**：ボタンが目立たなすぎると存在に気づかれない（Discoverability＝発見性の課題）。

---

### ④ Structured Controls / Tuners ＋ Hybrid（調整つまみ・構造化 UI ＋ 一言ハイブリッド型）
- **一次出典**：The Shape of AI（`Tuners` / `Inputs`）/ NN/g（GUI＋AI の融合）
- **どんな UI か**：スライダー・セグメントボタン・チェック・ドロップダウンなど **従来の分かりやすい GUI（Tuners）** でトーン・長さ・対象などの条件を確実に指定しつつ、必要時だけ短い自由入力（自然言語）を添えられる形。
- **向いている場面**：**8 割は毎回決まった条件だが、残り 2 割に現場ならではの例外や微調整が入る業務アプリ**（販促文作成、見積もり支援、画像調整、検索絞り込み等）。
- **メリット**：チャット型より圧倒的に速く、結果の品質も安定します。「プロンプトを書くのが苦手なお客さま」にもそのまま渡せます。

---

### ⑤ Ambient / Invisible ML（アンビエント・不可視／先回り型）
- **一次出典**：Apple HIG（**Invisible ML** / **Proactive vs. Reactive**）/ NN/g（**Ambient UI**）
- **どんな UI か**：**チャット欄も「AI を使う」ボタンも前面に出さず**、裏側で文脈や行動（Implicit シグナル）を読み取って自動分類・ゴーストテキスト予測入力・写真の自動補正・通知優先度整理・異常検知を行う形。噛み砕いて「裏方で静かに働く AI」と呼ばれることもあります。
- **向いている場面**：ユーザーが「AI を操作したい」のではなく、**いつもの道具を普通に使っているだけで勝手に便利になってほしい** 場面。
- **重要な原則（Apple HIG）**：
  - ユーザーが頼んでいないのに先回りする **Proactive（先回り）型** は、**間違えたときの不快感・許容度の低さが極端に厳しい** ため、非常に高い精度と「すぐに無視・オフ・元に戻せる逃げ道」が必須です。
  - ユーザーが入力中などに呼応する **Reactive（応答）型**（例：入力補完）の方が、多少外しても受け入れられやすいとされています。

---

### ⑥ Generative UI（ジェネレーティブ UI＝動的 UI 生成型）
- **一次出典**：NN/g（Outcome-Oriented Design / Generative UI）/ Vercel / Google
- **どんな UI か**：AI が文章だけを返すのではなく、ユーザーの依頼に応じて **比較表・グラフ・確認カード・カスタム入力フォーム・次のアクションボタンといった UI 部品そのものをその場で動的に組み立てて返す** 形。
- **従来のルールベース（固定画面）との違い**：従来の画面は開発者が「このメニューを押したらこの画面」と固定で作り込みます。一方 Generative UI では、ユーザーが自然言語で自由に尋ねた意図と取得データの構造を **AI 自身が判断して**、「数値比較だからグラフ部品」「日程調整だから予約フォーム部品」と最適な部品をリアルタイムに選んで組み合わせます。
- **向いている場面**：問い合わせ内容ごとに最適な見せ方が変わる場面（例：天気ならカード、売上比較ならグラフ、予約変更なら日時ピッカーを即座に出す）。
- **注意点（NN/g の指摘）**：画面構造が毎回変わるため、**あらかじめデザインシステムの部品カタログとアクセシビリティ規則（キーボード操作・読み上げ対応）を制約として与える** ことが不可欠です。

---

### ⑦ Agentic / Multi-step Workspace（自律エージェント・計画＆承認ワークスペース型）
- **一次出典**：Microsoft HAX Toolkit（G1・G2・G3・G7・G8・G9・G10 の Agentic UI 適用）/ Google PAIR
- **どんな UI か**：AI がツール呼び出しや複数ステップの作業を自律的に進めるアプリで、**① 実行前の計画（Plan）提示 → ② ステップごとの進捗タイムライン → ③ 外部送信・削除など重要操作の前の承認ゲート（Human-in-the-loop）→ ④ 途中停止（Stop）・差し戻し（Rollback）** を可視化する形。
- **向いている場面**：コーディングエージェント、自動調査レポート作成、複数システムをまたぐ業務自動化など、**数十秒〜数分かけて複数手順を自律実行する** 場面。
- **注意点（Microsoft HAX）**：途中経過がブラックボックスだとユーザーが過信または不信に陥るため、「今どの外部ツールを使ったか」「どこで失敗したか」を透明に表示し、いつでも介入できるようにします。

## 3. 7 パターン一覧比較表

| # | 一次用語（日本語の目安） | 主な提唱元・出典 | チャット欄 | いちばん向いている場面 | 最大の UX リスク |
|---|---|---|---|---|---|
| **1** | **Conversational / Chat**（会話型） | NN/g・Shape of AI | 主役 | 自由な相談・探索・ブレインストーミング | 会話の罠（毎回文章を打つ負担・白紙の恐怖） |
| **2** | **Canvas / Artifact**（成果物並列型） | NN/g・OpenAI/Anthropic | 左側など | 文書・コード・企画書の反復作成 | 画面幅の圧迫・版管理の複雑化 |
| **3** | **Inline / Contextual**（その場補助型） | NN/g・Apple HIG・MS | なし（局所） | 既存エディタやフォーム内での素早い書き直し・要約 | 機能の存在に気づかれにくい |
| **4** | **Tuners / Structured ＋ Hybrid**（調整UI＋一言） | Shape of AI・NN/g | 補助（任意） | 8割定型＋2割例外の業務アプリ・制作支援 | 部品が増えすぎると画面が煩雑になる |
| **5** | **Ambient / Invisible ML**（不可視・先回り型） | Apple HIG・NN/g | なし | 予測補完・自動分類・スマート通知・写真補正 | 先回り誤判定のストレス・制御不能感 |
| **6** | **Generative UI**（動的UI生成型） | NN/g・Google/Vercel | 起点のみ等 | 依頼ごとに表・グラフ・フォームを出し分けたい | 一貫性やアクセシビリティの崩壊 |
| **7** | **Agentic Workspace**（計画＆承認型） | Microsoft HAX・Google PAIR | 指示＋進捗 | 複数ステップの自律調査・自動化・外部連携 | ブラックボックス化・誤実行事故 |

> 💡 **実務の鉄則：1 つだけに縛られず「組み合わせる」**
> 優秀な実務アプリの多くは、たとえば **「④ Tuners（設定UI）＋ ② Canvas（右プレビュー）＋ ③ Inline（部分書き直し）」** や **「① Chat ＋ ⑥ Generative UI ＋ ⑦ 承認ゲート」** のように、2〜3 パターンを組み合わせて設計します。

## 4. 一次フレームワーク共通の AI UX 必須原則（6 つ）

Google PAIR・Apple HIG・Microsoft HAX に共通して強調されている原則です。

1. **できること・限界を最初に伝える（Microsoft G1・G2）**：AI に過大な期待を持たせず、お題チップや初期値で使い方を示す。
2. **フィードバックは暗黙（Implicit）を主、明示（Explicit）は要所だけ（Google PAIR / Apple HIG）**：毎回「👍/👎 を押してください」と迫ると疲れる（フィードバック疲れ）。編集・採用・スキップなどの自然な行動から学び、明示評価は重要な場面に絞る。
3. **不確かなときは無理に断定せず聞き返す・絞る（Microsoft G9）**：確信度が低いときは複数候補を出すか確認質問をする。
4. **取り返しのつかない操作の前に人間の承認を挟む（Human-in-the-loop / Microsoft G3・G7）**：送信・削除・公開・決済の前は必ず確認カードを出す。
5. **簡単なやり直し（Undo）と手動修正の逃げ道を用意する（Microsoft G8 / Apple HIG）**：AI が 95 点を出したあと、残り 5 点を人間が直接直せるようにする。
6. **裏側の詳細データは折りたたむ（Progressive Disclosure＝段階的開示）**：思考ログや JSON などの技術情報は最初から全開にせず、「詳細を見る ▼」へ収める。
